
# Тест-кейс: Проверка загрузки главной страницы GitHub

## Общая информация

| Параметр | Значение |
|---|---|
| **ID тест-кейса** | 01 |
| **Название** | Проверка загрузки главной страницы GitHub |
| **Модуль / Функциональность** | Главная страница |
| **Тип тестирования** | Функциональное, Smoke |
| **Приоритет** | High |
| **Серьёзность** | Critical |
| **Способ выполнения** | Ручное |
| **Связанный автотест** | `главная страница GitHub загружается с корректным title и контентом` |

## Цель тест-кейса

Убедиться, что главная страница GitHub доступна и корректно загружается: открывается по прямому URL, отображает контент и имеет корректный заголовок вкладки браузера.

## Предусловия

1. Есть устройство (ноутбук) с установленным браузером zen.
2. Есть стабильное подключение к сети Интернет.
3. Пользователь не авторизован на GitHub.
4. Кэш браузера очищен.

## Тестовые данные

| Данные | Значение |
|---|---|
| URL | `https://github.com/` |
| Ожидаемый title вкладки | Содержит слово «GitHub» |

## Шаги выполнения

| № | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | Открыть браузер с чистым профилем | Браузер открыт, история и кэш не используются |
| 2 | В адресной строке ввести `https://github.com/` и нажать Enter | Начинается загрузка страницы; в адресной строке отображается `https://github.com/` |
| 3 | Дождаться полной загрузки страницы | Страница загружена полностью, индикатор загрузки вкладки остановился, нет ошибок вида «Не удаётся получить доступ к сайту» / «502/503/504» |
| 4 | Проверить, что на странице отображается контент | Контент главной страницы виден и отрисован, отсутствуют сообщения об ошибках |
| 5 | Проверить заголовок вкладки браузера | Заголовок вкладки содержит «GitHub» |
| 6 | Проверить, что в адресной строке остался `https://github.com/` | URL соответствует главной странице, редиректов на сторонние домены/страницу логина нет |

## Ожидаемый общий результат

Все проверки пройдены — тест-кейс считается **Пройденным**. Главная страница GitHub успешно загружается, отображает контент и имеет корректный title, содержащий «GitHub».
=======


# Тест-кейс: Проверка отображения ключевых элементов навигации в шапке сайта

## Общая информация

| Параметр | Значение |
|---|---|
| **ID тест-кейса** | 02 |
| **Название** | Проверка отображения ключевых элементов навигации в шапке сайта |
| **Модуль / Функциональность** | Шапка сайта (Header / Navigation) |
| **Тип тестирования** | Функциональное, Smoke |
| **Приоритет** | High |
| **Серьёзность** | Major |
| **Способ выполнения** | Автоматизированное (Playwright) |
| **Связанный автотест** | `в хедере видны ключевые элементы навигации` |

## Цель тест-кейса

Убедиться, что в шапке (header) главной страницы отображаются ключевые элементы навигации и авторизации: ссылка на раздел «Pricing», а также ссылки «Sign in» и «Sign up». Пользователь должен видеть и иметь возможность использовать основную навигацию.

## Предусловия

1. Сайт доступен по тестируемому окружению.
2. Главная страница (`/`) доступна и отвечает без ошибок (2xx).
3. Тестовый браузер запущен (Playwright).
4. На странице присутствует элемент `header` с навигацией.

## Тестовые данные

| Данные | Значение |
|---|---|
| URL | `/` (главная страница тестируемого сайта) |
| Ожидаемые элементы в хедере | Ссылка «Pricing», ссылка «Sign in», ссылка «Sign up» |

## Шаги выполнения

| № | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | Открыть главную страницу `/` с ожиданием `domcontentloaded` | Страница загружена, DOM построен |
| 2 | Найти первый элемент `header` на странице | Элемент `header` найден |
| 3 | Проверить видимость `header` | `header` отображается пользователю (не скрыт, в пределах viewport) |
| 4 | Найти в `header` ссылку с текстом, содержащим «Pricing» | Ссылка «Pricing» найдена |
| 5 | Проверить видимость ссылки «Pricing» | Ссылка «Pricing» отображается |
| 6 | Найти в `header` ссылку с текстом, содержащим «Sign in» | Ссылка «Sign in» найдена |
| 7 | Проверить видимость ссылки «Sign in» | Ссылка «Sign in» отображается |
| 8 | Найти в `header` ссылку с текстом, содержащим «Sign up» | Ссылка «Sign up» найдена |
| 9 | Проверить видимость ссылки «Sign up» | Ссылка «Sign up» отображается |

## Ожидаемый общий результат

Все проверки пройдены — тест-кейс считается **PASSED**. В шапке главной страницы видны ссылки «Pricing», «Sign in» и «Sign up», навигация и точки входа в авторизацию доступны пользователю.


# Тест-кейс: Проверка страницы авторизации GitHub и её элементов

## Общая информация

| Параметр | Значение |
| :--- | :--- |
| **ID тест-кейса** | 05 |
| **Название** | Проверка доступности страницы логина GitHub, наличия полей ввода и валидации пустой отправки |
| **Модуль / Функциональность** | Авторизация (Login / GitHub) |
| **Тип тестирования** | Функциональное, Smoke, UI |
| **Приоритет** | High |
| **Серьёзность** | Critical |
| **Способ выполнения** | Ручное |
| **Связанный автотест** | Страница логина GitHub открывается, содержит поля ввода (`Username/email`, `Password`, кнопка `Sign in`) и корректно обрабатывает попытку отправки пустой формы |

---

## Цель тест-кейса
Убедиться, что страница авторизации GitHub корректно загружается, содержит обязательные элементы управления и предотвращает отправку пустой формы.

---

## Предусловия
1. Есть устройство с установленным браузером.
2. Пользователь не авторизован на GitHub.
3. Есть стабильное подключение к сети Интернет.
4. Кеш браузера очищен.

---

## Тестовые данные

| Данные | Значение |
| :--- | :--- |
| **URL** | `https://github.com/login` |
| **Ожидаемый URL** | Содержит `/login` |

---

## Шаги выполнения

| № | Шаг | Ожидаемый результат |
| :-: | :--- | :--- |
| **1** | Перейти по адресу `https://github.com/login` | Страница загрузилась |
| **2** | Проверить наличие поля для ввода имени пользователя или email | Поле с меткой "Username or email address" отображается на странице и доступно для взаимодействия |
| **3** | Проверить наличие поля для ввода пароля | Поле с меткой "Password" отображается на странице и доступно для взаимодействия |
| **4** | Проверить наличие кнопки входа | Кнопка "Sign in" отображается на странице |
| **5** | Оставить поля пустыми и нажать кнопку "Sign in" | Форма не отправляется, страница не перенаправляет пользователя, URL остается прежним. |

---

## Ожидаемый общий результат
Все проверки пройдены — тест-кейс считается пройденным. Страница логина GitHub успешно загружается, содержит все необходимые интерактивные элементы по точным меткам и корректно отрабатывает валидацию при попытке отправки пустой формы.

---

## Автоматизация
```typescript
test('Страница логина открывается и содержит поля ввода', async ({ page }) => {
  await page.goto('/login', { waitUntil: 'domcontentloaded' });

  await expect(page).toHaveURL(/login/);

  // Используем точные метки, которые использует GitHub
  await expect(page.getByLabel('Username or email address')).toBeVisible();
  await expect(page.getByLabel('Password')).toBeVisible();
  
  const signInBtn = page.getByRole('button', { name: /sign in/i }).first();
  await expect(signInBtn).toBeVisible();

  // Проверяем валидацию пустой отправки (страница не должна уходить с /login)
  await signInBtn.click();
  await expect(page).toHaveURL(/login/);
});
